# 문의게시판 이전 글 조회 및 검색 연결 수정

현재 브라우저가 서버의 전체 목록을 최신 50개 스냅샷으로 덮어써 오래된 상담이 사라져 보이는 문제를 해결한다. 기존 개별 상담 주소는 유지한다. 이 브랜치는 검토용이며 main 병합과 운영 배포는 사용자 승인 이후 진행한다.

## 변경 사항

- 일반 목록은 서버에서 10개씩 조회하며, 번호 링크·이전/다음 링크·자기 대표 주소를 유지한다. 브라우저의 과거 캐시와 실시간 리스너가 서버 목록을 덮어쓰지 않는다.
- 검색과 질환 분류는 모든 Firestore 이어보기 토큰을 따라가며, 예전 한글 분류명도 인식한다. GET 폼과 일반 링크로 동작한다. 검색·필터 URL은 noindex,follow로 중복 노출을 줄인다. 질환별 독립 콘텐츠 모음 페이지는 후속 작업이다.
- 사이트맵과 관련 질문 조회는 첫 300건 이후도 처리한다. 사이트맵에는 답변 본문이 있는 답변완료 글만 포함한다.
- 개별 상담의 제목·본문·답변·대표 주소·의료진 정보는 유지하며, 수정일은 최신 변경 시각을 반영한다. 실제 삭제·없는 주소는 404, 일시적인 데이터 연결 실패는 503으로 구분한다. 사이트맵 조회 실패도 빈/불완전한 200 응답을 내지 않는다.
- 관리자 화면의 100건 제한을 제거해 이전 글을 조회·답변·수정·삭제할 수 있게 한다.
- 새 상담 등록 성공 시 해당 글의 개별 페이지로 이동한다.

## 검증

- `node tests/test_inquiry_archive.js`: 651건, 66페이지의 누락·중복 없는 이동, 50/300건 이후 조회·검색, 기존 한글 분류, HTML escaping, 빈 검색, 페이지 범위, 사이트맵, 상세 SEO, 일시 오류, 브라우저 캐시 덮어쓰기 방지, 관리자 이전 글 조회 등 13개 시나리오 통과.
- `node tests/test_inquiry_ssr.js`: 8개 기존 SSR/검색 설정/관련 질문/사이트맵 시나리오 통과.
- `node tests/test_inquiry_reply_fix.js`: 기존 답변 저장·권한·작성자 표기 회귀 검사 통과.
- Hugo 0.165.0 extended로 전체 사이트 빌드 성공(286 pages). 기존 `.Site.Data` 사용에 대한 deprecation 경고는 남아 있다.
- `node tests/preview_inquiry_archive.mjs`: 실제 빌드된 목록 템플릿과 수정한 서버 함수를 이용해 독립 검토 HTML 생성. 실제 환자 데이터가 아닌 151개 예시 글을 사용한다. 첫 페이지·6페이지·16페이지·검색·질환 분류의 5개 화면을 선택할 수 있다.

## 운영 적용 전 확인 및 한계

- 운영 Firestore 자격증명을 사용한 새 count/query API 호출과 실제 브라우저 렌더링 검증은 아직 수행하지 않았다. 운영 적용 시 기존 서비스 계정으로 count 및 page 조회가 정상인지 확인해야 한다. 기존과 동일한 datastore 읽기 권한을 사용하며 새로운 쓰기 권한은 추가하지 않는다.
- 일반 목록은 count와 해당 페이지 10개를 읽는다. 깊은 페이지의 offset에는 Firestore 읽기 비용이 발생할 수 있다.
- 부분 문자열 검색·분류·관련 질문·사이트맵은 전체 문서의 이어보기 조회를 사용한다. 관리자도 전체 목록을 구독한다. 현재 제한을 없애기 위한 구현이며 글 수가 크게 증가하면 검색 색인과 관리자 페이지 조회를 별도로 도입할 수 있다.
- 단일 사이트맵의 표준 한도(50,000 URL)에 가까워지면 사이트맵 분할이 필요하다.
- 수집 가능성 개선이며 검색 순위·색인·AI 인용 결과를 보장하지 않는다.
